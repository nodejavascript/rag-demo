# rag — ask any document

**Paste an article, a diary, a resume or a set of terms. Then ask it questions.**
The answer quotes the document, and beside it you get the **dates**, **places**,
**people** and **images** it rests on — so you can check the answer instead of trusting
it.

Live at **https://rag.nodejavascript.com** · **private repo** `git@gitlab.com:dvsmcp/rag.git`

---

## Run it

```bash
npm install
docker compose -f ../docker-compose-master/docker-compose.yml up -d ollama   # a model to talk to
npm start                                                    # http://127.0.0.1:4500/
```

Default models: **`qwen2.5:7b`** writes the answers, **`nomic-embed-text`** does the
searching. Neither is required — see *Which model* below.

```bash
npm test            # 61 unit tests, no model needed, under a second
npm run test:e2e    # drives the real page in Chrome (skips if no model is up)
npm run eval        # 10 known questions, scored, against a live model
npm run calibrate   # measure the refusal floor for the current embedding model
```

| what | where |
|---|---|
| the model server, and the provider switch | `src/model.ts` |
| dates, and refusing to guess them | `src/dates.ts` |
| entries and notes | `src/chunk.ts` |
| places, people, amounts, pictures | `src/enrich.ts` |
| SQLite: FTS5 + vectors | `src/store.ts` |
| two searches + fusion | `src/retrieve.ts` |
| facts counted in code | `src/stats.ts` |
| the prompt, as a document | `src/prompt.ts` |
| the page and its charts | `src/site/app.ts` → `site/app.js` |

**`dist/` and `site/app.js` are generated by `tsc` — never edit them.** The build runs
twice, with separate tsconfigs, so Node types cannot leak into the browser code.

## The five decisions that make it honest

These are not preferences. Each is the answer to something that went wrong.

**1 · Counts are done in code, never by the model.** An early version handed a model
"47 of 263 entries" and it answered **"7"** — it had counted the eight notes it could
see. A model cannot count, so it is not asked to. Every figure shown is computed over
the whole document by `src/stats.ts`, and the prompt forbids recomputing it.

**2 · A date is claimed only when the day, the month and the year were all written.**
`March 2026` is a month, not a day. `06/03/2026` reads two ways and is quoted as
written, never resolved. A day-and-month with no year is carried forward from the
document — and the answer **says the year was worked out** rather than written.

**3 · Two refusals, not one.** Nothing matched at all → refused by the search, in
milliseconds, **without calling a model**. The subject is present but the detail is not
→ the model refuses, helped by a code-computed fact that a *name* appears nowhere.

**4 · The refusal threshold is measured, not felt.** An embedding always reports some
similarity, so "is this document about this at all?" has to be answered against a noise
floor. `npm run calibrate` measures it. **A different embedding model needs it measured
again** — the default was measured for `nomic-embed-text` and is not valid elsewhere.

**5 · The details beside an answer are found by the program, not written by the model.**
The dates, places, people, amounts and pictures are a **check on** the answer, not part
of it. That is the whole reason they are shown.

## Red lines, and where they are asserted

The worst failures in this kind of tool are not crashes. They are confident, plausible,
wrong statements. Each one below is a test in `test/`, so the heuristic cannot quietly
drift back.

| the failure | the rule that stops it |
|---|---|
| a document of short standalone lines split into 50 entries with EMPTY bodies | a heading needs the line beneath it to **end in a full stop** |
| an entire resume collapsed into one entry | a heading **alone in its own paragraph** starts an entry when the next paragraph is prose |
| a resume read as being located *in TypeScript* | a single word after a preposition is a place **only if the gazetteer knows it** |
| a person called **Built**; a person called **Better. Fixed** | a lone capital must appear **mid-sentence**, and a name must **end in a letter** |
| *Software Engineer* and *Computer Science* reported as people | a capitalised pair containing a role, an institution, a technology or a street type is not a person |
| the word *weather* reported as absent, so a question about rain was refused | an absent fact is asserted **only for a proper noun** |
| "UNIQUE constraint failed: chunks.id" on the second paste | ids are the **database's** to assign, not the document's |
| a fix deployed, and the old answer still served from the index cache | the reuse fingerprint includes a **`PIPELINE_VERSION`** |

## Which model

`src/model.ts` speaks two shapes and neither is baked in.

**`ollama`** — a model on the same machine. No key, no vendor, and the reason a local
build can promise nothing is uploaded.

**`openai`** — anything speaking the OpenAI HTTP shape, which includes **DigitalOcean
Gradient AI** (`https://inference.do-ai.run/v1`), DeepSeek, Groq, Together and OpenAI.

```bash
MODEL_PROVIDER=openai \
MODEL_BASE_URL=https://inference.do-ai.run/v1 \
MODEL_API_KEY_FILE=/run/secrets/do_token \
CHAT_MODEL=openai-gpt-oss-20b \
EMBED_MODEL=bge-m3 \
RERANK_MODEL=bge-reranker-v2-m3 \
npm start
```

**A hosted model changes the privacy claim, and the page says so.** With Ollama the
document never leaves the machine. With a hosted provider the notes that matched are
sent out to answer each question — nothing else, and not the whole document.

The reranker is optional and never blocks an answer: if the provider has no rerank
route the run continues on the fused ranking and says so in `warnings`.

## Two limits worth knowing

**A pasted document is capped at 400,000 characters** (`MAX_DOCUMENT_CHARS`). Past that
the index is slow to search and crowds out everything else on a 1 GB host. The refusal
says what the limit is and suggests splitting the text.

**A PDF is read by `pdftotext`, not by JavaScript.** A scan with no text layer comes
back empty and is refused **with that explanation** rather than silently indexed as
nothing.

## Deploying

The container publishes on **loopback only**; the Caddy on the host is what serves it.

```bash
docker compose up -d --build     # 127.0.0.1:4500
```

The memory limit in `docker-compose.yml` (384 MB) is not decoration: that host runs
nine other sites and a Postgres in 1 GB of RAM. An unbounded Node process plus a large
paste would take the whole machine down, and the blast radius would be every site, not
this one.

The document text and the questions are **never written to the log** — only sizes,
counts and timings. A privacy promise the log contradicts is not a promise.

## Gotchas paid for

- **An index cache is not keyed by the code that built it.** A document indexed with an
  old splitter kept being served after the fix, so the bug survived the fix. **Bump
  `PIPELINE_VERSION` whenever the chunker, the date parser, the enrichment or the
  stored schema changes.**
- **`CREATE TABLE IF NOT EXISTS` does nothing to a table that exists**, so a column
  added later never arrives on a used database — every index call failed with "no such
  column" on a deploy that already had a document in it. `#ensureColumn` exists.
- **A false failure is worse than no check.** Every bug found while building the tests
  was a wrong expectation, not a wrong implementation — except the four real ones, which
  were all found by trying to break a rule rather than by reading it.
- **Node's built-in SQLite needs `--experimental-sqlite` on 22 and ignores it on 24.**
  Passing it always keeps one start command working in both places.
